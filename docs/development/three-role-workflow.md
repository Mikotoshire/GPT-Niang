# 项目三角色工作流

AI 生成的维护配置与文档，未经充分验证或独立人工审查；AI 验收不是人工审查，也不保证真实显示 FPS。上游和第三方许可、署名及权利归属不变。

## 入口与模型来源

实现、配置和维护文档修改按规划 → 执行 → 全新上下文验收串行进行；普通问答与只读检查豁免。仅协调者分派，角色不递归启动流程；一次一个写入者，明确文件所有权并保留他人修改。协调者不直接写应用运行时代码。

优先使用全部三个已发现的用户角色 `team_planner`、`team_builder`、`team_verifier`；每次任务开始读取 `~/.codex/agents/team_{planner,builder,verifier}.toml` 的当前 model/effort，并遵循 `~/.codex/three-role-workflow.md`。三个用户文件是跨项目的共同模型来源；修改它们会控制未来采用这些角色的任务，本项目也优先跟随。不要把旧维护记录中的模型名当执行配置。

只有用户全局工作流完全不存在时，才使用保留的便携项目回退：`.codex/config.toml` 与 `.codex/agents/gptniang_{planner,builder,verifier}.toml`；这三个文件保持不变，其模型固定值仅对该回退有效。项目默认子代理模型不覆盖用户角色文件中的固定值。全局配置部分存在、无效或不可用时报告原因并请求修复，不静默回退旧模型。

检查实际角色元数据和来源，同名本地角色可能遮蔽全局角色并固定不同值，须披露冲突。当前聊天目录尚未加载时，用全新的内置 `default` 或确认没有固定模型/推理的可用角色，显式传入当前用户配置的 model/effort 和完整职责作为临时替代；推荐在仓库内新建聊天。现有会话不会因文件写入自动热加载，不静默修改信任设置。

严格解析、角色发现和实际模型调用是不同检查；核对实际 CLI 版本，不把旧版不支持的选项失败当成配置错误。支持时可用 `codex app-server --strict-config --print-startup-config`。自然语言流程不是硬门禁；只读指令不是独立沙箱，也不承诺固定费用节省。无需修改全局默认模型、容量、沙箱、审批、MCP、信任或插件。

## 交接与独立验收

1. 协调者保存原始用户需求、约束、基线 SHA/稳定内容哈希、允许范围、检查和回滚点；规划者只读取证，质疑假设，返回未知项、验收标准、文件所有权、计划及风险。
2. 执行者只修改分配文件，运行有意义的行为检查，不改预期刷绿；交接最终 SHA 或稳定哈希的未提交差异、实际命令/结果及局限。
3. 协调者以 `fork_turns="none"` 启动全新验收上下文。首轮只给原始需求、约束/标准、基线/最终快照、环境和范围，不给执行者根因/结论。验收者独立质疑计划、检查变更与测试并复现关键情景，之后再交叉核对执行证据。树有变化须重新绑定快照。
4. 验收返回 PASS、CHANGES_NEEDED 或 BLOCKED，附证据、命令/结果及未覆盖范围；可创建可丢弃测试产物，不编辑实现/测试预期，不提交、合并或发布。缺少独立上下文/环境必须 BLOCKED。修改后由执行者修复，再创建全新验收者。用户反馈优先于历史 AI 测试。
5. 同方向两次修复失败回到当前规划模型重新取证规划。释放阶段已完成代理；容量失败只允许一次有界重试，再失败报告阻塞，不省略验收或静默降级。项目现有容量上限不代表并行写入许可。

复杂或不确定的验收需升级时，使用全新内置 `default` 或确认没有固定 model/effort 的可用角色，显式指定当前验收模型/high，再按需当前规划模型/high，传入完整验收职责和独立首轮上下文。自定义文件固定值优先于 spawn 参数，不尝试覆盖固定 `team_verifier`；记录实际角色、模型、推理和升级原因。回退模式从项目文件读取对应当前值。

复用已安装 Superpowers/ECC 的现有入口，保留全新上下文、规格及质量审查和此处模型/独立性规则；不复制技能文本、不重复安装插件，缺少插件也不能跳过验证。

## 模型维护、项目授权与来源

模型手动更新只改三个用户原生角色文件的 model/model_reasoning_effort；先核对当前官方文档与账户可用目录，私下备份相关文件，再做解析、角色发现及最小只读调用检查，失败回滚。没有 latest 别名、自动升级、定时器或远端代码执行；聊天模型选择器不覆盖角色文件固定值。新会话推荐加载更新。

迁移只复制全局工作流五个文件（AGENTS.md、指南和三个角色文件），将 AGENTS 标记段合并到已有规则；不复制整套 `.codex`、auth、token 或 session，备份不入公开仓库。全局流程不授予提交、推送、发布或更改凭据/信任的通用权限。

本项目仍遵守 AGENTS.md 的隐私审计、许可证、备份、源码同步及发布授权；交付列变更、实际检查与局限、回滚点和实际角色。同步后核对精确远端提交的 CI 终态，排队/运行中不算通过；制作可分发安装包、创建发行标签或发布 Release 仍需明确请求；本地备份标签和 CI 内部打包校验按既有维护授权执行。本次仅配置/文档修改，不需应用 GUI 测试。

[OpenAI 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents) / [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 是配置来源；[ECC common workflows](https://github.com/affaan-m/ECC#common-workflows) 展示 planner/TDD/review 模式；[MLH 指南](https://static.mlh.io/docs/guides/parent-text.pdf) 描述黑客松构思、原型与演示，不能据此称三 AI 角色为普遍标准。不复制第三方代码或许可文本。
